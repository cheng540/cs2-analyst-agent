# 排障与常见坑

## SteamDT 批量取价限流（errorCode=4005）

批量价格接口 `/price/batch` 限制为 **1 次/分钟**，同一分钟内重复调用会返回
`errorCode=4005`。这是**瞬时限流，不是日额度用完**——等 65 秒重试即可。

代码里 `alerts.batch_retry_wait = 65` 就是这个等待时间。看到 4005 不要慌，
也不要立刻反复重试（只会一直失败）。

## `get_my_portfolio` 可能过期

网页问答的 `get_my_portfolio` 读的是**最近一次分析快照**。如果今天还没跑流水线，
它返回的是昨天的数据；快照里也可能含已卖出的条目，从而虚增市值。

要看真实敞口，用 `tools/probe_item.py --valuation`（实时取价重算）。

## 模拟盘同日幂等

`sim/paper.py` 同一天只执行一次（按日期做幂等判断）。所以手动重跑流水线是安全的，
不会重复建仓。改这块代码时**不要**破坏这个判断。

## Word 页数不能被估算

微软雅黑在 Word/WPS 里的实际行距约 **15.5pt/行**，不是排版理论上的 11.88pt。
按理论值估算会低估约 30% 的页数。

要页数就用 `tools/measure_docx_pages.ps1`（调 Word/WPS 实测），不要算。

## Windows 控制台编码

Windows 控制台默认 GBK，带中文/emoji 的 Python 脚本输出会 `UnicodeEncodeError`。
本地一律 `python -X utf8 ...`。

另外 PowerShell 5.1 按 GBK 读 `.ps1`，脚本里写中文注释会解析失败，
所以 `tools/*.ps1` 保持纯 ASCII。

## 改完代码要重启常驻服务

`tools/report_server.py` 是常驻进程，Python 不会自动重载已导入模块。改完代码
不重启，它会一直用内存里的旧逻辑——曾出现过费率改了但问答仍按旧口径回答的情况。

项目里加了 mtime 指纹守卫：被依赖文件变化时进程主动退出，交给 systemd 拉起。
`tools/*.py` 里的脚本不受影响（每次都是新进程）。

## 定期任务没跑怎么查

顺序：**先看日志 → 再看 `reports/` 有没有生成 Word → 最后才怀疑代码**。

日志在 `logs/`：`daily_run.log`（每日流水线）、`alerts.log`（每小时巡检）、
`weekly.log`（周报）、`report_server.log`（Web 服务）。
