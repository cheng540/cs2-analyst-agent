# 平台规则与交易口径

口径的**唯一真相源是代码**：`cs2analyst/rules.py`。这一节只是它的可检索说明，
两边不一致时以代码为准（并且要改代码 + 测试，不要只改这里）。

## T+7：买入后 7 天内不可卖出

平台执行 T+7 规则：饰品买入后 7 天内处于锁定期，**不能卖出、不能上架**。

含义：新买入的仓位在锁定期内**无法止损**。所以短线套利不现实，任何「买入后跌了就跑」
的策略在这个平台上是无效的。给建议时必须先确认这件饰品是否已解锁。

## 费率：卖出 1%，提现再 1%

- **买入不收手续费**；
- **卖出收 1%**，所得进入平台钱包（不是直接到银行卡）；
- **钱包提现再收 1%**。

所以同一笔卖出，成本要看钱接下来怎么用：

| 钱的去向 | 实际成本 |
|---|---|
| 继续留在钱包里买饰品（常见） | 约 1% |
| 提现成现金 | 约 1.99%（1% 卖出 + 1% 提现，复利） |

给建议时要把这两种口径分开说，不要笼统说「手续费很高」。

## 常见误解：2.5% 是错的

项目早期把费率写成 2.5%（一个从未核实的假设），导致所有盈亏算错，并一路传到
报告与提示词里。现在测试里有一条断言「2.5% 不得出现」。

教训：**没核实过的数字不能当作事实写进系统**。改费率必须同时改 `rules.py` 与测试。

## 分件成本与「剩余那件」

同一个物品买入多件时，平台的成本显示对应的是**剩余的那一件**，不是均价。

例：同款买过 ¥234 和 ¥164 两件，卖掉一件后，平台显示的可能是剩下那件的成本。
所以：
- 总额（总成本/总盈亏）不受影响；
- 但「这一笔卖出赚了多少」要对齐平台显示的到底是哪一件，否则和用户看到的数字对不上。

## 在售价 / 求购价 / 成交量

- **在售价（最低寄售价）**：别人挂出来的最低卖价，是「你现在能买到的价」；
- **求购价（最高求购）**：别人挂着收的价，是「你现在能马上卖掉的价」；
- **成交量/在售量**：决定流动性。在售量小而成交活跃 = 流动性好。

估值时用「在售价」做市值，用「求购价」估算「立刻卖能拿多少」，两者中间的差额
就是急卖的滑点。

## 卖出后必须立刻记账

卖出后如果不记账，日报会把**已经卖掉的**饰品当成持仓继续跟踪——实际出现过
「建议清仓一个已经卖掉的标的」。记账命令见 README 的「日常运维」。
