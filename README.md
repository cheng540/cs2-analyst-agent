# CS2 饰品持仓智能分析 Agent

基于 **SteamDT 开放平台** 行情数据的无人值守持仓分析系统：每日自动完成
**行情拉取 → 持仓同步 → 多维技术分析 → 独立决策 → Word 报告生成** 全链路，
替代人工盯盘与手动核算盈亏。

> 数据源：SteamDT 开放平台 API（https://doc.steamdt.com）
> 平台情绪指数仅作参考，操作建议由内置技术分析与仓位管理规则独立输出。

---

## 一、功能总览

| 模块 | 说明 |
| --- | --- |
| 大盘环境判断 | 大盘指数 + 日K/周K：MA5/10/20 多空排列、趋势判定（上升/震荡/下降）、风险等级（低/中/高）、操作总基调 |
| 持仓同步 | 本地 `config/inventory.json` 加载全部持仓（名称/磨损/数量/购入价/**分件成本**/用户意图），自动核算总市值与总盈亏 |
| 单品深度分析 | 价格位置百分位（近6个月）、均线系统、支撑压力位、流动性等级（在售/求购量）、量价分析 |
| 决策引擎 | 六因子评分 + 交易叙事 + 仓位管理，输出带**信心度/评分/目标仓位**的建议（🟢买入/加仓 · 🟡持有 · 🟠分批减仓 · 🔴清仓） |
| 模拟盘双轨 | A 轨纯规则 / B 轨规则+AI 对照实验，各 ¥3000，遵守 **T+7 锁定**与平台费率（卖出 1%、提现另 1%），每日记录净值与操盘手记 |
| 盘中巡检告警 | 每日 9:00–24:00 每小时巡检持仓与关注标的；**分级推送**（紧急即时推 / 温和静默记录，12:00 与 22:00 汇总） |
| AI 智能研判 | DeepSeek 模型解读大盘/情报/单品，给出立场与风险点，并**明确标注与规则引擎的分歧** |
| 网页问答 | 问答页：模型只能通过 7 个工具取数（含经验库检索），回答中的数字自动与工具数据**交叉校验** |
| 本地控制台 | 零构建 Web 控制台：**大盘 / 持仓 / 问一问 / 设置** 四页，可增删改持仓与参数（仅本机可写） |
| 配置向导 | 首次使用填 4 项（两个 Key、推送地址、持仓），不用手改 YAML；密钥只落本机、只回显掩码 |
| 经验库（RAG） | BM25 + 中文 bigram 检索「历史案例（当时判断 + 之后实际走势）/ 平台规则 / 饰品常识 / 官方公告」，零向量库依赖 |
| Word 报告 | 七段结构日报（大盘 / 组合 / 单品 / 建议汇总 / 风险 / AI 研判 / 模拟盘），自动归档 `reports/` |
| 每周复盘 | 每周日推送：双轨净值、持仓市值、**本周打扰了你几次**、已实现交易与成交价偏差，兼作运行心跳 |
| 定时调度 | 云服务器 cron：17:30 日报 · 每小时巡检 · 周日周报复盘（本地 Windows 计划任务为备份方案） |
| 容错 | 单饰品数据失败自动跳过、接口限额自动降级官网兜底、脏数据自动拦截，全流程不中断 |

### 申请 SteamDT API Key（免费）

1. 打开 https://www.steamdt.com 注册账号；
2. 进入「个人中心 → API管理」，申请开通 API Key（当前限时免费）；
3. 复制 Key 填入 `config/config.yaml` 的 `steamdt.api_key`。

### 填写持仓

三条路，按省事程度排：

| 方式 | 入口 | 说明 |
|---|---|---|
| **截图识别** | 控制台 → 持仓 →「从文本批量导入」→「上传截图识别」 | 走 DeepSeek 多模态（`deepseek-flash`，与 AI 研判同一把 Key），1–3 张、单张 ≤6MB；识别结果进预览表，确认后才写库 |
| **粘贴文本** | 同上 → 粘贴 → 解析 | 从平台库存页复制的文字，中文名会自动反查官方英文名；最稳、不花模型钱 |
| **逐条添加 / 改文件** | 持仓 →「＋ 新增持仓」，或直接编辑 `config/inventory.json` | 数量少、或要精确核对时用 |

> 三种方式共用同一套校验：名称反查、磨损档检查、总价/单价规则、重复项提示。
> **解析与识别都只给初值**，必须人工过一遍——名称错一个字符，系统会按另一个物品报价且不报错。

也可以直接编辑 `config/inventory.json`（可参考 `config/inventory.example.json`）：

```json
[
  {
    "market_hash_name": "AK-47 | Redline (Field-Tested)",
    "wear": "FT",
    "quantity": 2,
    "buy_price": 96.5,
    "buy_date": "2026-03-10",
    "platform": "YOUPIN",
    "special_style": "",
    "note": "",
    "manual_price": 0
  }
]
```

- `market_hash_name` 必须是 **Steam 官方英文完整名称**（含磨损后缀，如 `(Field-Tested)`）；
  悠悠有品/网易 BUFF 显示的是中文名（如「AWP | 尼罗河沃土 (崭新出厂)」），
  对应英文名为 `AWP | Black Nile (Factory New)`——可直接把中文名发我，我用官网数据帮你映射并校验。
- `manual_price`：**贴纸、印花等无 API 行情的品类**请填最新市价（元），系统会用它估值并
  在报告中标注「无技术分析」；行情类饰品留 0 即可，自动取实时价。
- 也支持 CSV（表头：`market_hash_name,wear,quantity,buy_price,buy_date,platform,special_style,note,manual_price`）。

## 三、AI Agent 工程要点（这个项目真正的技术含量在这里）

系统采用**混合架构**：规则引擎负责「事实与风控」，大模型负责「解读与判断」。为了让模型在**真实金钱场景**
里可用而不是添乱，做了这几件事：

### 1. 三层防幻觉（问答与研判共用）

| 防护层 | 做法 | 解决的问题 |
| --- | --- | --- |
| 事实归工具 | 模型只能通过 6 个工具取数（单品快照/技术分析/大盘/持仓/模拟盘/情报），系统提示词禁止凭记忆报价 | 杜绝编造价格与涨跌幅 |
| 数字交叉校验 | 回答生成后，程序提取其中的 ¥/% 等数字，逐一与工具返回数据比对，找不到即标注「未经验证」 | 把"算错/编数"挡在门外 |
| 依据透明 | 每条回答附带用了哪些工具与工具返回的原始数据 | 用户自己就能核对，不必相信模型的语气 |

### 2. 模型选型与思考模式（分场景配置）

同一份事实、同一个问题实测三种配置后的结论：**「开思考」比「换更大模型」划算得多**。

| 场景 | 模型 | 思考模式 | 理由 |
| --- | --- | --- | --- |
| 每日研判 / 模拟盘 B 轨 | `deepseek-flash` | 开 | 收益最大；后台任务不在乎 7 秒 |
| 网页问答 | `deepseek-flash` | 关 | 交互场景 + 多轮工具调用，延迟敏感 |
| 盘中告警点评 | `deepseek-flash` | 关 | 150 字短评，延迟优先 |
| 周报 / 月报复盘 | `deepseek-v4-pro` | 开 | 低频重活，用最强的 |

过程中踩到并修掉的四个坑：思考模式下 `temperature` 无效（不再发送）；**思考 token 会挤占
`max_tokens`，预算不足时接口返回空正文**（客户端自动加倍预算重试，仍为空则抛错而非静默返回空串）；
工具调用轮次正文本就为空、会被上述防护误判（`finish_reason=tool_calls` 放行）；
带 `tools` 的请求必须原样回传 `reasoning_content`，否则 400。

### 3. 告警分级：把「监控」和「打扰」分开

巡检频率提高到每小时 16 次后，如果沿用小节「有触发就推」，普跌日会收到十几条雷同消息——**用户一旦
不看，告警系统就等于废掉**。因此：

- **紧急（立即推）**：建仓信号 / 有效破位 / 盈亏跨档 / 单次跌≥4% / 单次涨≥6%
- **温和（静默记录）**：跌 3~4%、涨 4~6%、挂单骤变 → 由 12:00 与 22:00 的「盘中概览」汇总成一条
- **防轰炸闸门**：跌/涨两类紧急消息每天各上限 3 条，超出折叠进概览；建仓信号/破位/盈亏**永不折叠**
- **两次确认**：跌/涨/破位必须连续两次巡检都成立才推；判据是「**价格没有收复**」而非「信号再次触发」
  （跌 4% 后横住，第二轮根本不会再触发「较上次检查」，按后者永远确认不了）

### 4. 数据质量：真实踩过的坑（都在代码里留下了防御）

| 坑 | 现象 | 修法 |
| --- | --- | --- |
| 口径混比 | 批量接口给「挂单量」、官网兜底给「当日成交数」，退化后两种口径相减 → 假警报「挂单骤减 -99%」 | 给每个计数打口径标记，口径不一致直接跳过该规则 |
| 价格横跳 | 取「全平台最低价」，某境外平台那一行时有时无 → 同一饰品一天内跳 7%，报出假破位 | 告警基准改用用户实际交易平台报价 + 记录价源，价源变了不比较 |
| 脏数据 | 平台偶发返回 ¥0.09 占位价 → 报出「-99.92%」假警报 | 中位数 30% 阈值过滤 + 与上次/昨日价偏差超 60% 判定为异常 |
| 覆盖静默缩水 | 取价失败时只剩 8/18 个标的在监控，用户却以为「没消息 = 一切正常」 | 推送里写明覆盖度；批量接口失败先等 65 秒重试一次 |
| 名称版本错误 | 「纪念品版」写成普通版名 → 按另一个物品报价，估值差 2 倍，看起来像「流动性差」 | 加载持仓时做版本一致性检查（纪念品/Souvenir、暗金/StatTrak、★刀具） |

> 一句话总结这套系统的设计哲学：**模型只负责判断，事实必须来自代码；凡是会被用户当成事实的东西，
> 都要能追溯到数据源。**

## 四、决策引擎（v2：自由判断，非机械规则）

综合 **六因子评分 + 交易叙事 + 仓位管理** 输出带信心度的操作建议：

| 动作 | 触发逻辑 |
| --- | --- |
| 🟢 买入建仓 / 🟢 加仓 | 多因子评分达标（趋势/位置/量价/流动性/大盘背景/估值盈亏综合） |
| 🟡 持有观望 | 信号不明或评分中性，不追涨不杀跌 |
| 🟠 分批减仓 | 高位放量滞涨、浮盈过大、或评分转弱 |
| 🔴 清仓离场 | 有效跌破前支撑+放量下跌（形态破坏）、或评分极弱 |

**关键理念**（与机械规则的差异）：
- 大盘高风险是「敞口系数」（降仓位、提现金储备），**不是绝对禁止买入**——低位缩量止跌的左侧机会允许小仓试探；
- 深套但出现止跌信号时**先减仓而非盲目全清**（不砍在最低）；
- 盈利仓+占比过高+趋势转弱 → 减仓锁盈（而非「止损」）；
- 每个建议附带 **信心度（★1-5）、综合评分、目标仓位%**，全部阈值可配置。

## 五、模拟盘（纸上交易，双轨对照）

每日流水线用虚拟资金（默认 **¥3000**）对观察列表（`config/sim_watchlist.json`）执行操盘，
并**遵守平台 T+7 交易规则：买入后 7 天内不可卖出**（锁定期内的卖出指令自动顺延，报告与手记中标注可售日期）。

| 轨道 | 决策来源 | 说明 |
| --- | --- | --- |
| **A 轨** | 纯规则引擎 | 六因子评分 + 叙事 + 仓位管理 |
| **B 轨** | 规则 + AI 研判 | AI 拥有两种有限权限：**否决买入**（立场 avoid/reduce 或信心≤2）、**提议试仓**（立场 buy 且信心≥4，≤6% 权益） |

- 买入/加仓按「信心度 → 目标仓位」下单；**卖出收 1%**（悠悠有品买卖规则；卖出所得进平台钱包，
  提现另收 1%，不提现继续买则只有 1%）；
- **费率口径由 `cs2analyst/rules.py` 统一提供**（`fee_rates()` / `cashout_cost_pct()`），
  日报、网页问答、告警点评三处共用，避免口径漂移；
- 每日记录：净值、现金、持仓（含锁定期剩余天数）、成交明细、**操盘手记**；
- 同一日期只执行一次（幂等）；两轨各自独立账本（`data/sim/state_a.json` / `state_b.json`），
  一个月后可直接对比「纯规则 vs 规则+AI」的净值差异。

```bash
python main.py run            # 每日运行：分析 + 情报 + AI 研判 + 双轨模拟盘 + 报告
python main.py sim            # 查看双轨状态（净值/持仓/锁定期）
python main.py sim --reset    # 重置双轨（重新开始各 3000 元）
```

## 六、AI 智能研判层（DeepSeek）

采用**混合架构**：规则引擎负责「事实与风控」，大模型负责「解读与判断」。

| 层 | 职责 |
| --- | --- |
| 规则引擎 | 真实价格、指标、评分、仓位数学、止损纪律（永不越界） |
| 情报采集 | V社/CS2 官方更新记录（含官方**市场影响评级**）、市场涨跌异动（在售价/在售量/求购价变化） |
| AI 研判 | 解读更新公告对品类的影响、识别异动含义、给出每标的立场（buy/add/hold/reduce/avoid）+ 信心度 + 关键风险、明确指出与规则的分歧 |
| 留痕 | 每日研判存 `data/llm/YYYY-MM-DD.json`，情报存 `data/intel/`，供月末复盘 |

配置在 `config.yaml` 的 `llm` 段（`enabled` / `api_key` / `model` 等）；未配置 Key 时自动跳过，不影响主流程。

## 七、跨会话记忆（重要）

AI 的对话上下文会压缩、模型会切换、会话会重启——**只有写进文件的事实才可靠**。因此项目内置三层「落盘记忆」：

| 文件 | 作用 | 谁维护 |
| --- | --- | --- |
| `PROJECT_MEMO.md` | 项目全貌、用户偏好、当前状态、待办、交互记录表 | AI 每次交互后追加更新 |
| `data/journal/user_notes.md` | 用户每次来访说了什么、做了什么决定（追加式，不删改历史） | AI 每次交互后追加 |
| `data/brief_YYYY-MM-DD.md` | 由 `python main.py brief` 生成：持仓 + 双轨净值 + 最近手记 + 最新 AI 研判与情报 + 待办 | 命令自动生成 |

**下次来访（隔天 / 隔周 / 隔月）的恢复流程**：
```bash
python main.py brief     # 一条命令读回全貌
```
然后再读 `PROJECT_MEMO.md` 即可继续。用户若只说「今天不操作」，只需在 `user_notes.md` 追加一行；
若持仓有变动，改 `config/inventory.json` 后跑 `python main.py run`。

### 三条设计约束

1. **写数据的只有云端**。本地端默认只读，写接口只改 `config/`，从不写 `data/`、`reports/`。
2. **写接口只对 `127.0.0.1` 开放**。线上部署时把 `config/report_server.json` 的 `readonly` 设为 `true`，
   所有写接口返回 403；非本机来源同样 403。
3. **密钥不回传明文**。`GET /api/config` 只给 `sk-****1234` 掩码；前端密钥框永远留空，
   避免把掩码当新值提交（后端也会拒绝掩码值）。

### 并发写怎么办

cron 的 pipeline 与 Web 后端会同时碰 `config/`。所有写入统一走 `cs2analyst/web/store.py`：

- **文件锁**（Windows `msvcrt.locking` / POSIX `fcntl.flock`）；
- **原子替换**（写临时文件 → `os.replace`），读者永远看不到半截 JSON；
- **写前在锁内重读**，避免用旧内存副本覆盖别人刚写的内容；
- YAML 写入做**定点标量替换**，保留注释与键顺序；
- 每次写 `config/` 前自动备份 `*.bak.<时间戳-毫秒-PID>`（保留最近 10 份）。

有测试专门压这个：8 线程各写 50 次，最终计数必须一条不少（`tests/test_web_store.py`）。

## 十四、经验库（RAG）

分工是硬边界：

| 数据 | 用什么 | 原因 |
| --- | --- | --- |
| 价格、持仓、盈亏、净值 | **工具取数** | 必须精确 |
| 平台规则、饰品常识、官方公告 | RAG | 非结构化 |
| **历史案例**：某日的判断 + 之后实际走势 | RAG（最值钱的一条） | 能回答「上次类似形态怎么判断的、结果如何」 |

**持仓 JSON 绝不进检索库**。检索到的是「案例」（当时持有什么、怎么判断、后来怎么走），
当前持仓数字仍由工具提供——这正是防幻觉三件套的延伸，有测试断言语料里不含组合数字。

技术选型：**BM25 + 中文 bigram**，纯 Python、零依赖、内存极小。
不用向量库的原因：2C2G 服务器 + DeepSeek 没有 embedding 接口 + 语料只有几百篇，
上 Milvus/Qdrant 是给自己找麻烦。

```bash
python tools/build_rag_index.py                      # 重建索引（data/rag/index.json）
python tools/build_rag_index.py -q "纪念品 普通版"    # 重建并试检索
python tools/build_rag_index.py --stats              # 只看现有索引规模
```

语料来源：`knowledge/*.md`（手写知识，可自行增补）、`cs2analyst/rules.py`（规则镜像）、
`data/intel/`（官方公告）、`data/analysis/` + 单品 K 线（案例卡片）、`data/llm/`（每日研判）。

问答里它表现为第 7 个工具 `search_knowledge`：模型只能拿它解释「以前怎么判断」「为什么这样定规则」，
**要现在的价格必须换工具**。索引是个人数据，已在 `.gitignore` 内。

## 十五、开源发布与脱敏

发之前跑一次自检：

```bash
python tools/check_secrets.py       # 扫 Key / webhook / 服务器 IP / 明文密码 / 本机用户路径
python -X utf8 -m unittest discover -s tests -q
```

绝不能进仓库的东西：

| 类别 | 文件 |
| --- | --- |
| API Key | `config/config.yaml`（含 SteamDT / DeepSeek Key）、`config/*.bak.*` |
| 推送地址 | 企业微信机器人 webhook（泄露 = 别人能往你的群发消息） |
| 真实资产 | `config/inventory.json`、`data/`、`reports/`、`logs/` |
| 服务器信息 | IP、SSH key 路径、网页账号密码（`config/report_server.json`） |
| 私人材料 | `求职材料/`（默认不读、不提交） |

要点：

1. 密钥优先走环境变量（`STEAMDT_API_KEY` / `DEEPSEEK_API_KEY` / `WECOM_WEBHOOK`），
   它们优先级高于 `config.yaml`，开源演示时更安全；清单见 `.env.example`。
2. 如果密钥**曾经提交过**：先去服务商后台吊销并重新生成，再处理 git 历史——只删文件没用。
3. 从服务器拷下来的 `config/report_server.json` 里 `root` 是服务器路径，
   本地启动会自动回退到项目目录并打印提示（也可以用 `CS2_ROOT` 指定）。

## 十六、客户自助配置（报告开关 / 监控标的 / 巡检间隔）

目标：拿到项目的人**不用改代码、不用碰 crontab**，就能把系统调成自己想要的节奏。
三个入口都指向同一份配置（`config/config.yaml`）和同一套判断逻辑（`cs2analyst/policy.py`）。

### 16.1 三类报告各自开关

```yaml
reports:
  daily_enabled: true
  daily_time: "17:30"      # 日报：持仓分析 + Word + 推送
  noon_enabled: true
  noon_time: "12:10"       # 午报：盘中概览 + 体检 Word
  weekly_enabled: true
  weekly_day: 6            # 0=周一 … 6=周日
  weekly_time: "20:00"     # 周报：复盘 + 运行健康
```

关掉就是真的关掉：`tools/run_scheduled.py` 会跳过、不生成报告、不推送、也不占接口额度。
网页端在「设置 → 报告与巡检」，每一行还能看到「下次」几点跑。

### 16.2 巡检间隔

```yaml
alerts:
  enabled: true
  interval_minutes: 60     # 多久检查一次（15–1440）
```

下限 15 分钟不是随便定的：SteamDT 批量取价接口限制 **1 次/分钟**，设太密会一直吃
`errorCode=4005`，等于白烧额度。巡检只在 9:00–24:00 之间跑（夜里没有成交量）。

### 16.3 监控标的

- **持仓自动监控**：`config/inventory.json` 里的饰品不需要额外配置；
- **额外想盯的**：`config/sim_watchlist.json`，网页「设置 → 监控标的」可增删，上限 50 个；
- 加进来的标的会参与：日报分析、观察池评分、盘中巡检。

名称必须是 Steam 官方英文名（带磨损），例如 `AK-47 | Redline (Field-Tested)`。
写成中文、或漏了磨损档，系统会按另一个物品报价——纪念品 / 暗金 / ★ 刀最容易错。

### 16.4 改完怎么让它真的生效

| 部署方式 | 做法 |
|---|---|
| 服务器（cron） | `python tools/install_cron.py --install`（会先备份原 crontab，并清理旧的三行脚本任务） |
| 本地 Windows / 不想折腾 cron | `python main.py schedule` 常驻，按配置自动跑日报/午报/周报/巡检 |

`install_cron.py` 默认只**预览**不写入，确认无误再加 `--install`：

```text
30 17 * * *  ... tools/run_scheduled.py --task daily
10 12 * * *  ... tools/run_scheduled.py --task noon
0  20 * * 0  ... tools/run_scheduled.py --task weekly
*/30 9-23 * * *  ... tools/run_scheduled.py --task alerts   # interval_minutes=30
```

> 迁移提示：旧的三行（`daily_run.sh` / `run_alerts.sh` / `weekly_report.sh`）会被自动识别并移除，
> 避免同一天跑两遍。三个 `.sh` 保留下来当手动排查工具，内部也已改为走同一套开关。

## 附：Key 体检

「我明明配过了」是最高频的问题。配置里写着 Key ≠ Key 有效（可能吊销、余额不足、复制少一位），
界面上的「已配置」只代表非空。用一条命令看清真相：

```bash
python tools/check_keys.py                 # 打印生效 Key 的指纹 + 实际调接口验证
python tools/check_keys.py --offline       # 只看本地配置，不联网
python tools/check_keys.py --set-llm-key   # 交互式写入新 Key（不回显、不进历史）
```

它会告诉你：用的是配置文件还是环境变量、最后修改时间、`401/402` 具体含义、SteamDT Key 是否可用。
