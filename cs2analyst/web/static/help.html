CS2 持仓助手使用帮助
大盘 持仓 问一问 设置

三分钟上手（最短路径）

  1. 申请两个 Key：SteamDT（行情数据，免费）、DeepSeek（AI 研判与问答，按量付费，几块钱能用很久）。
  2. 打开控制台 http://127.0.0.1:8899/app/ → 设置 → 「首次配置向导」，把两个 Key 填进去。
  3. 同一页往下，用「⑤ 导入持仓」把你的持仓填进去（不会写就见 持仓怎么录）。
  4. 点「保存向导」→ 在项目目录执行 python main.py run，看能不能出报告。
  5. 想要推送，再看 企业微信 webhook；想要自动跑，看 定时与开关。
密钥只写进你本机的 config/config.yaml，不会上传、不会出现在网页源码里， 页面上只会显示 sk-****1234 这种掩码。

1. 获取 SteamDT API Key（行情数据）

这是行情数据源，系统的价格、K 线、成交都来自它。目前免费申请。

① 注册 / 登录打开 steamdt.com，用手机号或微信登录。
② 找到 API 管理进入「个人中心」，找 API 管理 / API Key 入口（不同版本文案略有差异，认准「API」两个字）。
③ 申请并复制点「申请 / 开通」，生成一串 32 位字符（形如 xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx），整串复制。
④ 填进系统控制台 → 设置 → ① SteamDT 开放平台 Key → 粘贴 → 保存；或直接写进 config/config.yaml 的 steamdt.api_key。
没有这个 Key 也能跑：系统会自动降级成「官网快照模式」——只用官网公开数据， 没有历史 K 线，所以均线、位置百分位、支撑压力这些技术指标算不出来，建议还是申请一个。

2. 获取 DeepSeek API Key（AI 研判）

负责日报里的「AI 研判」、盘中异动点评、网页「问一问」。没有它系统照样跑，只是这几块没有 AI 内容。

① 注册打开 platform.deepseek.com，注册并登录（手机号即可）。
② 充值左侧「充值」，充最小额度就够用很久：一次日报的研判大约几厘到几分钱，网页问答一次一两分钱。
③ 创建 Key左侧「API keys」→「创建 API key」→ 起个名字（比如 cs2-analyst）→ 复制。
④ 马上保存这串 sk- 开头的 Key 只显示一次，关掉弹窗就看不到明文了，先粘到安全的地方。
⑤ 填进系统控制台 → 设置 → ② DeepSeek API Key → 粘贴 → 保存。
如果控制台或日志出现 HTTP 401 ... api key is invalid，说明 Key 无效或已被吊销 （换过 Key、余额为 0 被停用、复制时少了字符都可能）。到 DeepSeek 后台重新生成一个再填。

不想把 Key 写进文件？用环境变量

环境变量优先级高于配置文件，适合服务器部署：

# Linux / macOS
export STEAMDT_API_KEY="你的 SteamDT Key"
export DEEPSEEK_API_KEY="sk-..."
export WECOM_WEBHOOK="https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=..."

# Windows PowerShell
setx STEAMDT_API_KEY "你的 SteamDT Key"
setx DEEPSEEK_API_KEY "sk-..."

3. 配置企业微信机器人 webhook（推送）

作用：每天的报告摘要 + Word 附件、盘中异动提醒、周报，都通过它发到你手机。 用一个只有你自己的群最合适（建群 → 踢掉别人 / 或用「文件传输助手」式的单人方式）。

3.1 建群并添加机器人（手机或电脑都可以）

① 建一个群企业微信 → 消息 → 右上角「+」→ 发起群聊 → 只选自己（或拉一个小号），群名随意，例如「CS2 播报」。
② 进群设置打开这个群 → 右上角「…」→ 找到 群机器人。
③ 添加机器人点「添加机器人」→ 新建 → 起个名字（如「持仓助手」）→ 确定。
④ 复制 Webhook 地址添加完成后会显示一串地址，形如 https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key= 后面跟一串由字母数字和短横线组成的字符，整体点「复制」。
⑤ 填进系统控制台 → 设置 → ③ 企业微信机器人 webhook → 粘贴 → 保存。

3.2 验证是否通了

在项目目录执行：

python tools/send_test_push.py

群里应该立刻收到一条测试消息。收不到就按顺序查：

现象原因与处理
提示「未配置推送地址」webhook 没填，或 notify.enabled: false。去设置页确认。
报 errcode 93000webhook 地址不完整（少了 key= 后面的部分）或已被删除。
群里没有任何消息，也不报错机器人被移出群了；或你复制的是另一个群的地址。
日报有文字但没 Word 附件附件上限 20MB；报告过大或上传接口异常时只发文字，属正常降级。
webhook 就是密码。拿到这串地址的人可以往你的群里发消息。 不要截图发出去、不要提交到 GitHub（项目已把 config/ 排除在仓库外， tools/check_secrets.py 也会在打包前扫一遍）。泄露了就回群设置里删掉机器人重建。

4. 录入你自己的持仓

先澄清两件事，避免白折腾：
  • 「问一问」改不了持仓。它是只读问答（查行情、看分析、讲规则），不写任何数据。
  • 持仓是「录入一次、之后维护」的东西，不是每天填。买入/卖出后才需要改。

三种录入方式，按省事程度排

方式适合入口
截图识别手上是平台库存截图，十几条懒得敲 持仓 →「从文本批量导入」→「上传截图识别」
粘贴文本能从平台复制出文字（最稳） 持仓 →「从文本批量导入」→ 粘贴 → 解析
逐条添加只有一两件，或者要精确核对 持仓 →「＋ 新增持仓」
无论哪种方式，最后都要你在预览表里核对一遍。 模型和解析器都可能把「总价」当「单价」、把磨损档看错。名称错一个字符， 系统就会按另一个物品报价，而且不会报错。

方式 0：截图识别（用 DeepSeek 多模态）

  1. 先在「设置」里配好 DeepSeek Key（识图和 AI 研判共用这一把，不需要另配视觉模型）。
  2. 持仓 →「从文本批量导入」→ 点「上传截图识别」，选 1–3 张库存截图。
  3. 等 5–15 秒，下面会出现预览表：每行标着「可导入 / 要核对 / 需补全」，旁边列出可疑点。
  4. 逐行改错的字段 → 选「追加」或「替换全部」→「确认导入」。
  • 限制：单张 ≤6MB，最多 3 张；识别按量计费（一次几分钱）。
  • 图要清楚：饰品名、数量、单价尽量都完整，别截一半。
  • 点「看模型从图里读出的原文」可以核对它到底抄了什么——排错最快的方式。

方式 A：网页逐条添加（最不容易写错）

  1. 打开控制台 → 持仓 页 → 下方「持仓原始记录」→「＋ 新增持仓」。
  2. 填英文标准名（见下）、数量、买入均价、买入日期、是否已过 T+7，保存。
  3. 已有条目点「改」可以修改，点「删」移除（删除前会自动备份）。

方式 C：网页批量粘贴（一次贴一批）

控制台 → 持仓 →「从文本批量导入」→ 粘贴平台复制出来的几行 → 解析 → 核对 → 导入。 支持「名称 数量 单价」「名称 ×2 ¥169」「中文名（会自动反查英文名）」等写法。

如果你手上已经是标准 JSON，也可以用 设置 → 向导第 ⑤ 项整体写入：

[
  {"market_hash_name": "AK-47 | Redline (Field-Tested)", "quantity": 1,
   "buy_price": 169.0, "buy_date": "2026-09-20", "unlocked": true,
   "note": "中文名：AK-47 | 红线 (久经沙场)"},
  {"market_hash_name": "Glove Case", "quantity": 2, "buy_price": 92.0,
   "lots": [94.0, 92.0], "unlocked": true, "note": "手套武器箱，两件不同成本"}
]

注意：向导里的导入是「整体写入」——粘贴的内容会成为完整持仓列表， 不是在末尾追加。只想加一条请用方式 A。

方式 D：直接改文件

编辑 config/inventory.json（格式同上），保存后下次运行即读取。适合一次录入很多条。

字段说明（哪些必填）

字段必填说明
market_hash_name是Steam 官方英文名，必须带磨损档，如 AK-47 | Redline (Field-Tested)。写错会按另一个物品报价。
quantity是件数，整数。
buy_price是买入均价（元）。多件不同价时用下面的 lots。
lots否分件成本数组，如 [94, 92]。用于「先卖哪一件更划算」的分析。不填则按均价展开。
buy_date建议填买入日期 YYYY-MM-DD。T+7 锁定期靠它推算。
unlocked否true = 已过 7 天可以卖。没记日期但确定早就解锁时填 true。
wear否磨损档代码：FN / MW / FT / WW / BS。仅用于展示与校验。
note否备注，建议写中文名，报告里更好认。
名称写错是这里最常见的坑。三种版本是完全不同的物品，价格能差几倍：
  • 纪念品：英文名以 Souvenir 开头，没有暗金版本；
  • 暗金：英文名里带 StatTrak™；
  • 刀具/手套：英文名以 ★ 开头。
系统检测到「备注写纪念品、英文名却不是 Souvenir」这类矛盾会在日志里警告，但那只是提醒，仍然会按英文名报价。

5. 额外监控别的饰品

持仓里的饰品自动监控，不用另外加。你想盯但还没买的（准备入手、或者只是看看），走这里：

  1. 控制台 → 设置 → 「监控标的」→ 输入框填英文名（同样要带磨损档）→「添加」。
  2. 加进去的标的会参与：日报的观察池评分、盘中巡检、以及「最接近买点」的信号提醒。
  3. 上限 50 个；太多会拉长每轮取价时间，也更费接口额度。

对应的文件是 config/sim_watchlist.json，也可以直接编辑。

6. 定时任务与报告开关

三类报告和盘中巡检都能单独开关，时间也能改。入口：控制台 → 设置 → 「报告与巡检」。

项目默认说明
日报每天 17:30持仓分析 + 决策 + AI 研判 + Word 报告 + 推送
午报每天 12:10盘中概览 + 全部监控标的的体检 Word
周报周日 20:00双轨模拟盘 + 持仓 + 已实现交易 + 运行健康
盘中巡检每 60 分钟价格异动分级推送；只在 9:00–24:00 跑

让改动生效

  • 自己有服务器（Linux）：执行 python tools/install_cron.py --install。 它会按当前配置重写 cron（先备份原 crontab，并清掉旧的三行脚本任务，避免一天跑两遍）。 只想看看会写成什么，去掉 --install 即可。
  • 在自己电脑上（Windows / macOS）：不用碰计划任务，直接常驻 python main.py schedule，它按配置自动跑。
巡检间隔别设太密：SteamDT 批量取价接口限制 1 次/分钟，低于 15 分钟会频繁返回 errorCode=4005（限流），既拿不到数据也浪费额度。

8. 常见问题

控制台打不开 / 一片空白

  • 服务没启动：在项目目录执行 python tools/report_server.py，看到「控制台：http://127.0.0.1:8899/app/」再开浏览器。
  • 提示要登录：账号密码在 config/report_server.json（默认 cs2 / change-me）。 本机嫌麻烦，可以把 local_no_auth 设成 true，127.0.0.1 访问就免密码。
  • 页面上全是「暂无数据」：还没跑过分析。先 python main.py run 或 python main.py demo。

数据不更新 / 还停在几天前

  • 看「大盘」页顶部的黄色提示，会写数据是几天前的。
  • 本地控制台只读云端同步下来的数据。要拉最新：powershell -File tools\sync_from_server.ps1， 或者在本机直接 python main.py run。

报 errorCode=4005

SteamDT 限流：批量取价接口 1 次/分钟。等 65 秒会自动重试（代码里已经处理）。 如果频繁出现，把巡检间隔调大，或减少监控标的数量。

我明明配了 Key，为什么还报 401 / 提示未配置？

九成是「填了但没保存」，或者「保存到了另一份配置」。按顺序查：

  1. 项目目录执行 python tools/check_keys.py：它会打印当前真正生效的 Key 指纹 （前 5 位 + 后 4 位 + 修改时间），并真的调一次接口。
    如果指纹和你手上那把不一样，说明没写进去。
  2. 在网页「设置 → DeepSeek Key」重新粘贴后，必须点「保存这一组」（不会自动保存）。 密钥框留空表示"不修改"，不会把旧值清掉。
  3. 命令行写入（输入不回显、不进 shell 历史）： python tools/check_keys.py --set-llm-key
  4. 如果服务器上设了环境变量 DEEPSEEK_API_KEY，它会覆盖配置文件—— 这种情况下改文件没用，要改环境变量。

日报里没有「AI 研判」

九成是 DeepSeek Key 无效或余额不足。日志里搜 401 能看到具体原因。 系统会降级继续跑（报告照出，只是没有 AI 段落），不会整体失败。

想换电脑 / 搬家

把这些带走即可：config/（含持仓与密钥）、data/（历史与账本）、reports/。 其余代码重新解压一份就行。

截图识别准不准？

读文字（饰品名、数字）比较准，但有三类地方会错，必须你自己看： 磨损档漏写或多写、把总价当单价、把「在售数量」当成「你持有的数量」。 所以识别结果一律进预览表，标出「要核对 / 需补全」，你确认后才写库。 图糊、字小、截图只截一半时，请改用「粘贴文本」。

数据会不会被上传？

不会。持仓、报告、日志全部在你本机（config/、data/、reports/）。 出网的只有：行情请求（SteamDT）、AI 研判与问答（DeepSeek，内容是行情事实与分析结论，不含账户信息）、 推送（你自己群的 webhook）。

还有问题？先看项目根目录的 README.md，里面有更偏开发的说明。
